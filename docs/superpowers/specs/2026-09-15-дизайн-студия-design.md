# PostBot как дизайн-студия

Дата: 15.09.2026. Статус: спека, кода по ней нет. Утверждена владельцем в разговоре
15.09 («Да, записывай спеку»).

Заменяет дорожную карту спеки `2026-09-15-конвейер-карусели-design.md`. Из неё
остаются в силе решения владельца, профилактика до первой картинки, чек-лист
осмотра и лестница правки. Фаза 1 оттуда (`предполёт.py`, реестр
`docs/дефекты-кадров.md`) уже в master. Фаза 3 (кнопки сценария в боте) снята:
бот и приложение — пульт студии, их в этой работе не трогаем.

## Зачем

PostBot производит контент как дизайн-студия: клиент даёт заказ, студия
согласует замысел, верстает, проверяет и сдаёт. Сейчас студия устроена так,
что лучшие работы делаются в обход неё:

- три стиля последних дней — «пары», «подборка сайтов», «подборка GitHub» —
  живут отдельными скриптами в `4xSoft/исследование-тикток-карусели/шаблоны`
  (`рисовать.py` по 300–370 строк, половина функций одинаковая: шрифты,
  страница, кот, обложка, финал, выгрузка). Папка не в git;
- такие посты не попадают в базу: повтор темы никто не видит, «Выложил руками»
  не нажать;
- дизайн и вёрстка перемешаны в `card.py` на 3800 строк: чтобы поправить один
  стиль, сессия читает весь файл (41 чтение за неделю по замеру 14.09);
- проверки кадра разные у бота и у сессионных шаблонов, реестр дефектов один
  только у бота;
- по замеру 14.09 больше 80% лимита Claude уходит на сессии разработки, а не на
  модель бота.

Цель: каждая карусель идёт через студию, по одному порядку, с проверками до и
после вёрстки. Дорогое мышление тратится только на решения, остальное делают
скрипты и дешёвые исполнители.

## Решения владельца, которые действуют

1. Сценарий выбирает только владелец.
2. Claude может отметить карусель «годен» по чек-листу осмотра.
3. Правок не больше двух кругов, но карусель после них не выбрасывается:
   кадр убирается, сливается или ждёт починки макета.
4. Хвост буквы, зашедший на плашку призыва, — брак.
5. Разработка без живых прогонов: без генерации на настоящей модели, без
   черновиков в базе, без массовой отрисовки ради проверки. Юнит-тесты — да.
6. Лимит Claude беречь: готовый план выполняет один агент на Sonnet в
   изолированной копии, итог сверяется один раз.
7. База фактов `facts.py` запрещена (`facts.РАЗРЕШЕНЫ = False`).
8. Пульт (бот, веб-приложение) в этой работе не меняется.

## Роли

| Роль | Отвечает за | Где в PostBot | Исполнитель |
|---|---|---|---|
| Клиент | бриф, выбор сценария, итог | владелец | — |
| Продюсер | очередь, учёт, повторы тем | `jobs`, база, `темы.py` | скрипты |
| Редактор | о чём пост и зачем: польза, что сохраняют, референсы | `ideas.py`, `source.py`, `вдохновение.py`, разборы владельца | Claude, коротко |
| Копирайтер | сценарий и тексты в поля макета | `carousel.сочинить`, `writer.py`, `humanizer.py` | модель бота |
| Арт-директор | выбор макета под бриф, бренд-бук, приём новых макетов | `форматы.py`, скил `визуал-слайдов` | Claude, редко |
| Дизайнер | новые макеты: референс → паспорт → прототип → библиотека | скилы `визуал-слайдов`, `style-analyst`, `hallmark` | сильная модель, отдельная смена |
| Верстальщик | заполняет готовый макет данными и отрисовывает | движок студии, `браузер.py` | скрипт |
| Выпускающий | препресс до вёрстки и после, лист, чек-лист | `предполёт.py`, `приёмка.py`, `замер.py`, `лист.py` | скрипты + Claude смотрит один лист |
| Архив | бренд-бук, макеты, ассеты, эталоны, дефекты, разборы | `assets/`, `docs/дефекты-кадров.md`, память | — |

**Правило разделения:** верстальщик не придумывает дизайн, дизайнер не верстает
заказ. Новый макет никогда не делается внутри заказа — это отдельная работа
дизайнера, и в заказ он попадает только из библиотеки.

## Ход заказа

```
Бриф → Концепция → Согласование → Вёрстка → Препресс → Показ → Правки (≤2) → Сдача → Архив
```

| Стадия | Что происходит | Выход | Ворота |
|---|---|---|---|
| Бриф | тема или референс, что сохраняют, призыв | запись заказа в базе | тема не повторяет последние (журнал всех заказов); не запрещённая |
| Концепция | арт-директор выбирает макет из библиотеки; копирайтер пишет данные в поля макета | данные поста + сценарий `.md`, собранный из них | препресс-1: поля, пределы макета, обещание обложки, простой язык, следы ИИ, валюта, призыв |
| Согласование | клиент видит сценарий | «рисовать» / правка / другой / отказ | без «рисовать» дальше не идёт |
| Вёрстка | движок заполняет макет, одна отрисовка за раз, прогретый Chrome | кадры | препресс-0: ассеты на месте, картинки открываются, значок не заглушка |
| Препресс | проверка каждого кадра; лист кадров | отчёт текстом + лист | препресс-2: запас между блоками, текст за краем, невидимый текст, порванное слово, картинка не загрузилась, размер. Брак останавливает |
| Показ | осмотр листа по чек-листу | годен / кадр N | Claude или клиент |
| Правки | лестница: кадр, не карусель; не больше двух кругов | исправленные кадры | причина в макете — ремонт макета, а не заказа |
| Сдача | папка на столе: JPG 1080×1440, подпись, сценарий | пост в базе | годен по препрессу и осмотру |
| Архив | разборы клиента, дефекты, журнал | записи | — |

## Библиотека макетов

Макет — стиль кадров, отделённый от движка. У каждого макета:

- `ДИЗАЙН.md` — что за стиль, откуда (паспорт референса), правила, свои пункты
  чек-листа осмотра;
- **поля** — из каких кадров состоит пост и что в каждом: имя поля,
  обязательность, предел (знаков, пунктов, строк). Одни и те же поля читают
  копирайтер (задание модели), препресс-1 (проверка) и сценарий `.md` (показ);
- **разметка** — функции, которые по данным поста отдают HTML каждого кадра;
- свои ассеты (значки, узоры), если нужны.

**Движок** — общее для всех макетов: встроенные шрифты, страница кадра, кот и
знак из бренд-бука, отрисовка через `браузер.py`, препресс-2 на каждом кадре,
выгрузка JPG на стол с подписью, лист кадров, запись заказа в базу.

Место в репозитории — пакет `студия/` в корне PostBot: `студия/движок.py`,
`студия/макеты/<имя>/`. Точное деление модулей решает план шага 1.

Бренд-бук — одна запись о цветах, гарнитурах, знаке, полосе и коте, из которой
берут все макеты. Сейчас эти значения разбросаны по `card.py`, `config.py` и
трём `рисовать.py`.

## Препресс

- **Препресс-0 (ассеты):** каждый файл, на который ссылаются данные, существует,
  открывается, не пустой; значок не страница-заглушка.
- **Препресс-1 (данные, до вёрстки):** `предполёт.py`, но пределы берутся из
  полей макета, а не из общих чисел `carousel.ЗАГОЛОВОК_ДО` и `МЫСЛЬ`.
- **Препресс-2 (кадр):** проверки `card._принять` и замер запаса между блоками
  (`шаблоны/запас.py`, в PostBot — работа копии `zapas-blokov` из другого окна;
  студия берёт её после сведения, а не пишет вторую).
- **Осмотр:** один лист кадров на карусель; общий чек-лист из спеки
  конвейера плюс пункты из `ДИЗАЙН.md` макета.

Пункт чек-листа уходит в препресс-2, когда его ловит автоматика без ложных
тревог. Реестр дефектов общий для всех макетов: `docs/дефекты-кадров.md`.

## Расход

| Работа | Исполнитель | Почему |
|---|---|---|
| вёрстка, препресс, лист, выгрузка, учёт | скрипты | 0 токенов |
| бриф, выбор макета, осмотр | Claude, короткая смена | решение, но небольшое; осмотр — одна картинка |
| сценарий в поля | модель бота (`claude -p` без обвеса) | маленький контекст вместо большой сессии |
| сверка фактов и ассетов | агент на Sonnet | поиск, не творчество |
| новый макет | сильная модель, отдельная смена | редко, и только вне заказа |
| разработка студии | один агент на Sonnet по плану с полным кодом | как фаза 1 |

Правила смен: одна смена — одна стадия, работа передаётся файлом или записью в
базе, а не памятью разговора. Дешёвые стадии пакетом (N сценариев разом),
вёрстка поштучно. Код движка в смене не читается: хватает команды студии и
`ДИЗАЙН.md` макета.

## Дорожная карта

Каждый шаг — отдельный план и отдельная копия, без живых прогонов.

### Шаг 1. Библиотека макетов и движок
- [ ] Пакет `студия/`: движок и библиотека.
- [ ] Перенести «пары», «подборка сайтов», «подборка GitHub» **без изменения
      вида**. Доказательство — HTML кадров совпадает с тем, что дают нынешние
      `рисовать.py` на тех же постах (`двойники.json`, `вайбкодер.json`,
      `дизайн-от-ии.json`, `лето.json`, `замены.json`). Снимок подменяется, как
      в `tests/test_вид_на_всех_связках.py`: Chrome не нужен.
- [ ] Заказ такого макета пишется в базу: пост со своими кадрами и подписью,
      «Выложил руками» работает.
- [ ] Команда студии для смены: проверить данные, сверстать (все кадры или
      номера), лист с отчётом, сдать.
- [ ] Сессионные шаблоны после переноса не удаляются, а помечаются
      «перенесено в PostBot» в их `ДИЗАЙН.md`.

### Шаг 2. Препресс для каждого макета
- [ ] Поля с пределами у каждого макета; `предполёт.py` читает пределы макета.
- [ ] Сценарий `.md` на согласование собирается из данных поста.
- [ ] Препресс-2 в движке для всех макетов; запас между блоками — после
      сведения копии `zapas-blokov`.
- [ ] Лист кадров и текстовый отчёт после каждой вёрстки; чек-лист из
      `ДИЗАЙН.md`.
- [ ] Хвост буквы на призыве — брак (решение 4).

### Шаг 3. Архив
- [ ] Ассеты с проверкой: значки (`значок-браузером.mjs`), снимки сайтов
      (`снять.mjs`), картинки репозиториев — один путь для всех макетов.
- [ ] Журнал заказов: каждый пост в базе, темы сверяются по нему; подключить
      `темы.py`.
- [ ] Сверка фактов при посте (цены, звёзды, переименования с датой) — **только
      после отдельного слова владельца**: запрет базы фактов (решение 7) может
      это покрывать.

### Шаг 4. Регламент студии
- [ ] Скил `студия`: роли, ход заказа, команды, правила смен и расхода. Заменяет
      `конвейер-карусели`, который описывает путь через бота.
- [ ] Учёт: на заказ — стадии, круги правки, брак по типам, отказы клиента и
      их причины.

### Шаг 5. Дизайны `card.py` в библиотеку
- [ ] По одному дизайну за план, тем же способом: HTML до и после совпадает.
- [ ] Матрица запретов `форматы.НЕЛЬЗЯ` переезжает в поля своих макетов.
- [ ] Прогон образцов и примерка из спеки конвейера — здесь, для макетов из
      `card.py`, когда владелец разрешит прогон.

## Вне рамок

- Кнопки и экраны бота, веб-приложение, облачная копия `vercel/`.
- Новые макеты: они идут через дизайнера после шага 1.
- Починка дефектов из реестра — по Контуру Р, отдельными планами.

## Что проверить в плане шага 1

- Чем три `рисовать.py` отличаются в общих функциях (`данные`, `фейсы`,
  `страница`, `кот`, `обложка`, `финал`, `main`): совпадают дословно или
  разошлись. Разошедшееся становится параметром макета, а не общим кодом.
- Как сейчас выгружается подпись и сценарий на стол, чтобы `выгрузка.py` бота и
  движок студии не разошлись.
- Где хранятся ассеты постов (значки, снимки сайтов, картинки репозиториев) и
  сколько места они займут в репозитории.
