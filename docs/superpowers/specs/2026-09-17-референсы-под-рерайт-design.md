# База референсов под рерайт

## Зачем

Владелец кидает ссылки на чужие посты в Telegram: группа-форум «Полезное»,
тема «Под рерайт». Когда он говорит «возьми референс из базы и сделай
сценарий», Claude должен видеть очередь, взять оттуда ссылку и не взять одну
и ту же дважды. Сейчас ссылки лежат только в переписке, учёта нет.

Первый шаг — **только запись**. Скачивание кадров, разбор, раздел в
приложении и ответ в личку не делаются: их добавят потом поверх той же
таблицы.

## Как устроено

Три части, у каждой одна задача.

**1. Таблица `references` в базе постбота** (`db.py`, в `СХЕМА`). База та же:
SQLite на маке без `DATABASE_URL`, Postgres в Supabase с ним.

| колонка | что |
|---|---|
| `id` | сквозной номер |
| `url` | ссылка, приведённая к одному виду; `UNIQUE` |
| `площадка` | `instagram`, `tiktok` или `другое` |
| `tg_message_id` | номер сообщения в теме, откуда ссылка |
| `добавлена` | дата сообщения в Telegram, ISO |
| `статус` | `новая` → `в работе` → `использована`; или `отброшена` |
| `post_id` | номер поста, в который ушёл референс; пусто до того |
| `заметка` | свободный текст, пусто по умолчанию |

Приведение ссылки: у Instagram и TikTok отрезаются параметры (`?img_index=…`,
`&stkn=…`), иначе один и тот же пост, скинутый с разных кадров, ляжет дважды.
Короткие `vt.tiktok.com/…` сохраняются как есть — раскрывать их значит ходить
в сеть, это уже не «только запись».

**2. Сбор: модуль `референсы.py`.**

- Где читать — константы в модуле: группа `-1004462031298`, тема `14`.
- `сверить()` — через сессию аккаунта (`userbot`) читает сообщения темы новее
  курсора, достаёт из каждого все ссылки (сущности текста и адреса в тексте),
  пишет строки, повторы по `url` молча пропускает. Курсор — номер последнего
  прочитанного сообщения, хранится настройкой `референсы.курсор` (`db.запомнить`);
  двигается и сообщениями без ссылок. Возвращает число новых.
- `пора()` — не чаще раза в 5 минут, по образцу `уборка.пора()`.
- В `bot.главный_цикл` — ещё один блок `try` рядом с уборкой: `if пора(): сверить()`.
  Ошибка сети или Telegram печатается и не роняет бота; следующий круг
  повторит, курсор не сдвинется.
- Сессия не настроена (`userbot.вошли()` ложно) — сбор тихо выключен.

Почему аккаунт, а не бот в группе: история темы хранится без срока, поэтому
всё, что пришло, пока мак спал, добирается следующим кругом. Бота не надо
делать админом группы, одна дорога вместо двух.

**3. Команда для Claude: `tools_референсы.py`.**

- `список [статус]` — очередь, по умолчанию `новая`, старые сверху.
- `взять [id]` — без номера берёт самую старую новую; ставит `в работе`,
  печатает ссылку.
- `готово <id> <post_id>` — `использована` и номер поста.
- `отбросить <id> [причина]` — `отброшена`, причина в `заметка`.
- `сверить` — сбор вручную, не дожидаясь бота. Сессию читает в память
  (копия), чтобы не сцепиться с живым ботом за файл.

## Чего не делаем сейчас

Скачивание кадров и текста, разбор, раздел «Референсы» в приложении, ответ в
личку, раскрытие коротких ссылок, чтение других тем группы.

## Проверка

Тесты в `tests/test_референсы.py` на SQLite, без сети:

- приведение ссылок: Instagram с параметрами и без дают одно; TikTok короткая
  не меняется;
- извлечение всех ссылок из сообщения, в том числе нескольких в одном;
- повторная запись той же ссылки не создаёт вторую строку;
- курсор двигается и на сообщении без ссылок, не двигается при ошибке чтения;
- `взять` без номера отдаёт самую старую `новая` и меняет её статус.

Живая проверка: `tools_референсы.py сверить` на настоящей теме кладёт шесть
ссылок, что лежат там на 17.09, повторный запуск — ноль новых.
