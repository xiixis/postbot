# Instagram, Facebook, Threads по API и вертикаль 4:5

Решено с владельцем 22.09.2026.

## Зачем

Посты должны сами выходить в Instagram, на страницу Facebook и в Threads, как
сейчас выходят в TikTok. Пересылка «из Instagram в остальные сети Meta» здесь
не поможет: переключатель автопубликации в приложении срабатывает только на
посты, выложенные руками, а посты из API он не пересылает. Поэтому в каждую
сеть пост отправляется отдельно, но все три работают через одно
Meta-приложение.

API Instagram принимает кадры с пропорциями от 4:5 до 1.91:1. Наш формат 3:4
(1080×1440) он отвергает. Владелец решил перевести **все вертикальные кадры на
4:5 (1080×1350)**, и TikTok тоже. Кадры не обрезаются и не получают поля по
бокам: для 4:5 делается своя вёрстка.

## Исходное состояние

- Аккаунт Instagram профессиональный и уже связан со страницей Facebook.
- `threads.py` написан и есть в реестре `площадки.py`, но в `.env` нет
  `THREADS_TOKEN` и `THREADS_USER_ID`. Поэтому площадка не считается готовой.
- Кода для Instagram и Facebook нет.
- Размер 3:4 прописан в `card.py` (`ФОРМАТЫ["3к4"]`), `carousel.py`
  (`ФОРМАТ["tiktok"]`), `площадки.py`, в копиях `vercel/card.py` и
  `vercel/площадки.py`, в общем коде стилей (`Style/стиль.py`: `W, H = 1620, 2160`;
  `Style/выпуск.py`: 1080×1440; `Style/замер.py`), в `холст.py` и `рисовать.py`
  каждого стиля, в `tools_днк.py`, `tools_дизайны.py` и примерно в тридцати
  тестах.

Работа идёт двумя этапами. Они не зависят друг от друга, и их можно вести
одновременно.

## Этап 1. Формат 4:5 для всех вертикальных кадров

**Что меняется**

- `card.py`: вместо `ФОРМАТЫ["3к4"]` появляется `ФОРМАТЫ["4к5"]` 1080×1350.
  Поля и кегли пересчитываются заново, а не сжимаются пропорционально: высота
  стала меньше на 90 px, и верхнее и нижнее поля должны оставить место для
  интерфейса TikTok (подпись занимает нижние ~180 px). Действуют прежние нормы:
  крупная строка — 14–16% высоты кадра, соотношение старшего кегля к младшему
  3:1, запас между блоками 40 px на кадре высотой 1620.
- `carousel.py`: `ФОРМАТ = {"телеграм": "квадрат", "tiktok": "4к5", "instagram": "4к5"}`.
- `площадки.py`: TikTok получает `"формат": "4к5"`. Instagram заводится с
  `"формат": "4к5"`, `"файл": "jpeg"`, `"ширина": 1080`, `"картинок": 10`,
  `"подпись": 2200`.
- `Style/стиль.py`: рабочий кадр `W, H = 1620, 2025` (это 1080×1350 в полуторном
  масштабе). `Style/выпуск.py` снимает и сохраняет 1080×1350. `Style/замер.py`
  и пороги ДНК пересчитываются от новой высоты.
- Каждый стиль в `Style/*/`: его `холст.py` и `рисовать.py` переверстать под
  новую высоту. Сжать вёрстку по вертикали недостаточно, нужна своя раскладка
  (правило «новый стиль значит новая вёрстка»).
- `vercel/card.py` и `vercel/площадки.py` повторяют правки основного дерева.
- Старое имя `3к4`: в записях базы оно считается как `4к5`, чтобы черновики,
  сохранённые до переезда, не сломались.
- Телеграм остаётся квадратным, форматы `широкий` и `вертикаль` не трогаются.

**Проверка**

- Тесты с 1440 и `3к4` переводятся на новый размер, весь набор тестов проходит.
- Каждый стиль отрисовывается один раз — отрисовки идут по одной, не
  параллельно. Лист кадров «было 3:4 / стало 4:5» проверяю глазами: текст не
  обрезан, логотип на каждом кадре, между блоками не меньше 40 px, приёмка
  кадров без брака.
- `tools_днк.py` прогоняется по всем стилям с новыми порогами.

## Этап 2. Публикация в Meta через Graph API

**Подход.** Свои модули на Graph API, так же как TikTok и X. Сервис-посредник
отклонён: он платный, получает доступ к аккаунтам, а схема площадок у нас уже
есть.

**Ключи**

- Одно приложение на developers.facebook.com, владелец в нём администратор.
  Для своих аккаунтов проверка приложения Meta (App Review) не нужна.
- Вход через Facebook с правами `instagram_basic`, `instagram_content_publish`,
  `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`. Короткий
  ключ пользователя меняется на долгоживущий, из него берётся **бессрочный
  ключ страницы**. Этим ключом публикуем и в Instagram, и на страницу.
- В `.env` и в облако кладутся `META_PAGE_TOKEN`, `META_PAGE_ID`, `IG_USER_ID`.
  Облачные ключи — через `ключи_облака.py`, как у остальных площадок.
- Для Threads — отдельный вход в том же приложении. Ключ `THREADS_TOKEN` живёт
  60 дней. Раз в неделю задача в `jobs.py` продлевает его через
  `th_refresh_token` и записывает новый туда же, где лежит старый. Если
  продление не удалось, бот предупреждает владельца.
- Ключи получаем вместе: владелец входит в Meta, я веду по шагам и проверяю
  каждый ключ запросом `/me`.

**Модули**

- `instagram.py` — `настроен()`, `опубликовать(подпись, картинки) -> str`.
  На каждый кадр создаётся контейнер (`/{ig}/media`, `is_carousel_item=true`),
  затем контейнер карусели (`media_type=CAROUSEL`, `children`, `caption`).
  Статус опрашивается, пока не станет `FINISHED`; при `ERROR` или по тайм-ауту
  через 5 минут выдаётся ошибка. Потом `/{ig}/media_publish`. Если кадр один,
  вместо карусели публикуется одиночный пост. Работает с кадрами 4:5 в JPEG,
  не больше 10 штук. Если кадров больше, публикация отказывает с понятной
  причиной, а не обрезает пост молча.
- `facebook.py` — `настроен()`, `опубликовать(текст, картинки) -> str`.
  Каждый кадр загружается в `/{page}/photos` с `published=false`, затем
  выходит `/{page}/feed` с `attached_media` и `message`.
- `threads.py` не меняется.
- Общий разбор ответа Graph API вынести в одну функцию, если в
  `instagram.py` и `facebook.py` получится одинаковый код. Выносить заранее
  не нужно.

**Встраивание**

- `площадки.py`: записи `instagram` и `facebook`, `ПОРЯДОК` дополняется,
  `готова()` проверяет их `настроен()`.
- `publish.в_площадку` и `в_сеть`: ветки для `instagram` и `facebook`.
- `варианты.py` и `crosspost.py`: подпись для Instagram и Facebook берётся из
  версии для TikTok (живая речь и 6–8 хештегов, до 2200 знаков) без нового
  запроса к модели. Правило «хештеги всегда» остаётся в силе.
- В кнопки бота и мини-приложения площадки попадают сами, через
  `площадки.готовые()`.

**Ошибки**

- Отказ одной площадки не останавливает остальные. Причина пишется в отметку
  этой площадки (`варианты.отметить`), и её видно в боте.
- Повторная отправка идёт только туда, где у поста ещё нет следа публикации,
  иначе будут дубли.
- Предел в 100 публикаций через API за сутки мы не превысим, отдельно его не
  проверяем.

**Проверка**

- Тесты `instagram.py` и `facebook.py` с подменённым `requests`: порядок
  запросов, поля, ожидание `FINISHED`, отказ на 11 кадрах, разбор ошибки
  Graph API.
- Настоящий прогон: тестовая карусель из двух кадров 4:5 уходит в каждую из
  трёх сетей. Я смотрю, что пост появился, затем удаляю его через API.
  Если удаление через API недоступно, удаляет владелец.
- `postbot-ревизия` перед выкаткой в облако.
