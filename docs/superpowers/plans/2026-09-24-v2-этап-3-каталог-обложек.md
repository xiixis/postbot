# Конвейер v2, этап 3: каталог обложек и команда сборки — план выполнения

> Спека: `docs/superpowers/specs/2026-09-24-v2-этап-3-каталог-обложек-design.md`.
> Выполняется inline (executing-plans), в копии `conveyor-v2-stage3`.

**Цель.** Запасные обложки берутся из проверенного каталога в теме стиля; одна команда
сверяет снабжение, собирает, принимает и печатает параметры выкладки.

## Ограничения

- Тема стиля даёт цвета, шрифты, поля; макет даёт устройство. Макет может держать свою
  светлоту (`Макет.тёмный`): «списание» — тёмный кадр и в светлом стиле (его выбрал владелец
  главной 24.09).
- Перенос из рисовальщиков — без изменения вида: снимки запасных обоих постов 24.09 до и после
  совпадают (сверка пикселями, средняя разница < 0,5 уровня из 255).
- Кот из карточки сцены — блок `кот-сцены` с `data-вылет`: судится за «впритык», но не за край
  и не за зону кнопок (сцены 24.09 с котом справа приняты владельцем; новые сцены снабженец
  рисует с котом левее 900 — записано в `маскот/README.md`).
- Chrome — один, сборки последовательно.

## Задачи

1. **Каталог `Style/обложки.py`** — `Тема`, `Макет`, `МАКЕТЫ` (замена, списание, превращение,
   плёнка, число, сцена), `проверить`, `файлы`, `кот_сцены`, `доски_обложек`. Тесты
   `tests/test_обложки.py`: нехватка полей; каждый макет × темы «пар» и «сервисов» → приёмка
   годен (Chrome); текст, севший на кота сцены, → «впритык».
2. **Подключить «пары» и «сервисы».** `ТЕМА` в `категории.py` и `карточка.py`; посты 24.09 —
   на `"запасные"`, `"холст"`; старые функции запасных удалить. Сверка пикселями с
   `scratchpad/до-каталога/`. Главные со сценой получают блок кота из карточки.
3. **Команда `Style/карусель.py`** — снабжение, проверка обложек, сборка, итог с параметрами
   выкладки. Тесты `tests/test_карусель.py`.
4. **Записать** — `ПУБЛИКАЦИЯ.md` (шаг 5), роль приёмщика и снабженца, план v2, память;
   полный прогон тестов; сведение в master.
