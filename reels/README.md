# Ролики канала

Вертикальные ролики для Reels и TikTok. Собираются кодом в Remotion: кадр — это страница,
ролик — её состояния во времени. Мышь и монтажная программа не нужны.

## Установка

Зависимости перечислены в `package.json`: Remotion, GSAP и Three.js. Ставятся в эту же
папку: `npm install`. Папка `node_modules` своя, с `yt-searcher` она не связана.

На маке владельца общий кэш npm (`~/.npm`) содержит файлы, принадлежащие администратору,
и обычная установка падает с `EACCES`. Лечится один раз: `sudo chown -R 501:20 ~/.npm`.
До этого ставить с отдельным кэшем: `npm install --cache /tmp/npm-cache`.

## Команды

Все из папки `reels`.

```
npm run list                                  # какие ролики есть
npm run stills -- ClaudeMontage 0 100 262     # кадры в out/ClaudeMontage/
npm run studio                                # смотреть и двигать в браузере
npx remotion render src/index.ts ClaudeMontage out/video.mp4 --props=out/props-none.json --codec=h264 --crf=15 --pixel-format=yuv420p --concurrency=2
npx remotion render src/index.ts ClaudeMontage out/sfx.wav --props=out/props-none.json     # только звуки, 10 секунд
bash tools/mix.sh out/video.mp4 out/sfx.wav public/claude-montage/music-a.m4a out/reel-a.mp4 2.95 4.55
```

Кадры рендерятся три минуты, звук десять секунд. Поэтому видео считается один раз без
музыки, а звук и музыка подкладываются отдельно: правка звука не требует пересчёта кадров.
Два числа в конце `mix.sh` — отрезок в секундах, где музыка приглушается под набор на
клавиатуре.

Музыка выбирается настройкой `music`: `a`, `b`, `c`, `d`, `e` или `none`. Значение передаётся файлом:
`--props=out/props.json`, внутри `{ "music": "b" }`.

У роликов `ClaudeWords`, `ClaudeKeys` и `ClaudeDesk` музыка у каждого своя, настройка `music`
только включает её: `{ "music": false }` для рендера кадров и звуков под сведение.

## Озвучка

Голос делает Fish Audio, модель `s2.1-pro-free`. Питон берётся у 4xTube: там стоят
`requests` и `faster-whisper`. Ключ читается из `FISH_API_KEY` или из облака команды
4xTube и живёт только в памяти процесса.

```
~/4xSoft/yt-searcher/.venv/bin/python3 tools/voice.py voice/v2-words.json        # все голоса
~/4xSoft/yt-searcher/.venv/bin/python3 tools/voice.py voice/v2-words.json А-рассказчик
npx remotion render src/index.ts ClaudeWords out/v2-sfx.wav --props=out/props-off.json
~/4xSoft/yt-searcher/.venv/bin/python3 tools/voice-mix.py out                     # out: где лежат ролики без голоса
~/4xSoft/yt-searcher/.venv/bin/python3 tools/voice-check.py
```

Текст ролика лежит в `voice/<ролик>.json`: у каждой фразы окно «с … до» в секундах. Окна
стоят на состояниях ролика, поэтому голос не уезжает от картинки. Фраза с пометкой
«к концу» прижимается к концу окна: так «И жму Энтер» кончается на звуке клавиши.

Правила озвучки, проверенные на деле:

- Голоса только обезличенные. В библиотеке Fish много голосов, снятых с живых людей и
  персонажей: в ролики канала они не идут.
- Фраза на состояние: четыре-пять коротких слов на такт. Голоса говорят с разной
  скоростью, от 2 до 3 слов в секунду, текст пишется под самый медленный.
- Ускорять голос можно до 1,2. На 1,17 распознавание уже теряло слова.
- Озвучка каждый раз немного разная. Неудачный дубль переснимается, удачный хранится.
- Речь громче музыки под ней хотя бы на 10 дБ. При 3–7 дБ низкий голос тонул.
- Музыка опускается по времени фраз, а не самим голосом: прижатие голосом давало от 4
  до 10 дБ, у каждого голоса своё.
- Иностранные слова пишутся так, как звучат: Клод, Телеграм, Энтер.
- **Ролик, где голос ведёт, озвучивается одним запросом** (`tools/voice-one.py`), а не по фразе.
  По фразе модель каждый раз заново выбирает голос: высота гуляла на ±15%, настроение скакало,
  перечисление повисало. Одним запросом и с одной манерой голос ровный, интонацию задаёт структура
  текста. Разбор текста по ролям строк — образец в `src/r11-plugins/ОЗВУЧКА.md`.
- Перечисление через запятую звучит незаконченным: каждому слову своя точка.
- Ударение в трудном слове ставится значком в поле `"голосу"` строки («о́тступы»).
- Пустая строка между абзацами в тексте для Fish даёт лишний звук: абзацы идут с новой строки.
- Скрипт в `tools/` нельзя называть именем модуля питона: `wave.py` заслонил
  стандартный `wave`, и озвучка падала на первой строке.

## Вторая серия: один каркас, три умения

Спека: `../docs/superpowers/specs/2026-09-30-ролики-серия-2-сценарии.md`. Двенадцать тактов по
2,4 с: крючок, промпт, скилы, показ на пять тактов, «сохрани», призыв. Общие части лежат в
`src/series/parts.tsx`, сетка в `src/series/grid.ts`. Новый ролик серии: своя папка с показом,
остальное берётся готовым.

Субтитры по словам: после озвучки `tools/words.py voice/r6.json А-рассказчик` кладёт время
слов в `src/series/words/r6.json`, ролик читает файл при сборке. Пока файла нет, субтитров
нет, ролик собирается. Порядок: озвучка → время слов → рендер кадров → сведение.

Проверено на деле:

- В вертикальном кадре кольцо карточек целиком не помещается и сверху видно только рёбра.
  Винт вокруг оси читается: камера поднимается по оси, карточки проходят перед ней по одной.
- Картинка на карточке нужна с обеих сторон, иначе снаружи винт выглядит пустым.
- Снимок на тёмном фоне под цвет страницы не выравнивается (`tools/flat.py` темнит героя):
  край прячет мягкая радиальная маска.
- Первый кадр партии `stills` у сцены с текстурами иногда выходит пустым: текстуры ещё
  грузятся. Кадр снимается отдельно ещё раз, а у готового видео первые кадры проверяются.

## Два движка: Remotion и HyperFrames

С 2 октября 2026 ролик можно собрать тремя способами. Проверено на одном и том же ролике
`r10-plugins` (57,9 с, 1737 кадров, 22 состояния), вид у всех трёх одинаковый.

| Способ | Как устроен | Команда |
|---|---|---|
| Remotion | React-композиция `Plugins`: сцены ставит по кадру `lib/gsap.ts`, заголовок рисует React | `npx remotion render src/index.ts Plugins out/r10-remotion.mp4 …` |
| HyperFrames | одна страница `hf/r10-plugins/index.html`: разметка, один таймлайн GSAP, звук тегом `<audio>` | `cd hf/r10-plugins && npx hyperframes render` |
| Гибрид | сцены снимает HyperFrames в `public/plugins/hf-scenes.mp4`, заголовок, знак и звук кладёт Remotion (`PluginsHybrid`) | оба шага подряд |

Все три разом: `sh tools/r10-render.sh`, время каждого ляжет в `out/times.txt`.

Замер 02.10.2026 на этом маке (M1 Pro, 16 ГБ), 1747 кадров 1080×1920 со звуком, два прогона:

| Способ | Рендер | Файл | Что это значит |
|---|---|---|---|
| HyperFrames | 47–48 с | 29 МБ | быстрее реального времени; четыре вкладки снимают кадры снимками экрана |
| Remotion | 88–90 с | 17,5 МБ | в 1,9 раза дольше при `--concurrency=2`; файл легче, `crf 17` |
| Гибрид | 42–43 с + 112–114 с | 22 МБ | самый долгий: сцены считаются в HyperFrames, потом Remotion перекодирует их вместе с заголовком |

Картинка у трёх одинаковая: средняя разница кадров 1–3 единицы из 255, это сжатие.
Гибрид оправдан, когда поверх готовых сцен нужно то, что удобнее в React: субтитры по
словам из данных, варианты заголовка, пакет роликов с разным текстом на одной картинке.
Для одного ролика он только добавляет второй проход.

Что делает такой ролик возможным:

- **Сцены не знают про движок.** `shared/scenes.js` отдаёт разметку строкой и собирает
  таймлайн GSAP на паузе. Remotion ставит его головку по номеру кадра, HyperFrames
  перематывает сам. Поэтому в таймлайне нет обратных вызовов: счёт числа идёт твином
  `textContent`, набор текста — буквами с прозрачностью, рисование линии — штрихом.
- **Преобразования в CSS стоят только на обёртках.** То, что двигает GSAP, в CSS не
  наклоняется: иначе проверка HyperFrames падает с `gsap_css_transform_conflict`.
- **Селекторы склеиваются плюсом.** На шаблонной строке внутри `querySelector` падает разбор
  HyperFrames (`template_literal_selector`).
- **В рендере HyperFrames сети нет.** Шрифты (`public/plugins/fonts`), GSAP и картинки
  кладёт рядом со страницей `tools/hf-build.mjs`.
- **Проверка до рендера:** `npx hyperframes check` в папке проекта. Она ловит наложение
  текста, выход за кадр и слабый контраст на каждом состоянии. Нарочный декор помечается
  `data-layout-ignore`. До правок было 90 замечаний, после — ноль.
- **Скилы HyperFrames не обновлять его командами.** В настройках стоит
  `HYPERFRAMES_SKIP_SKILLS=1`, наборы ставит `.claude/наборы-скилов.py`. Файлы `CLAUDE.md` и
  `AGENTS.md`, которые кладёт `hyperframes init`, из проекта удаляются: правила уже в скилах.

## Голос ведёт: раскладка по записанным фразам

У первых роликов окна фраз стояли на тактах музыки. У `r10-plugins` наоборот: время сцен
снимается с голоса, потому что референс так устроен.

```
~/4xSoft/yt-searcher/.venv/bin/python3 tools/voice.py voice/r10.json А-рассказчик    # записать фразы
~/4xSoft/yt-searcher/.venv/bin/python3 tools/layout.py voice/r10.json А-рассказчик   # время сцен и слов
~/4xSoft/yt-searcher/.venv/bin/python3 tools/sound.py voice/r10.json А-рассказчик    # голос + музыка + переходы
sh tools/r10-render.sh
```

В сценарии фраза — это одно состояние ролика: у неё `ид`, `пауза` после и `не короче`.
Раскладка пишет `src/r10-plugins/timeline.json`: начало и конец каждой сцены и время каждого
слова (`w[ид][номер]`). По нему встают и предметы в сценах, и слова заголовка.

Проверено на деле:

- Длинную фразу из двух-трёх предложений записывать отдельными фразами. Иначе голос
  проговаривает её за четыре секунды, и на состояние выходит по 1,2–2 с: мельтешит.
  После разбиения ролик вышел 57,9 с против 50,6 с, состояния по 2,1–3,6 с.
- Чужие названия писать, как звучат: Гиперфреймс, Ремоушен, Тэйст скилл, Импэкабл, Версель,
  Линеар. Распознавание на них всё равно спотыкается (сходство 0,67–0,75), поэтому эти
  фразы слушает владелец.

## Ролик с голосом: порядок, который даёт результат с первого раза

Собрано на роликах r10 и r11 (2–3 октября 2026): всё, что владелец правил руками, здесь стоит
правилом. Образец целиком — `src/r11-plugins/` и `voice/r11.json`.

**Движок.** HyperFrames: рендер быстрее реального времени и есть проверка до рендера. Remotion —
когда нужен объём (Three.js) или пачка роликов на одном шаблоне.

**Текст.**
1. Первая фраза говорит результат, а не перечень: «Этот ролик никто не монтировал», а не «5 плагинов».
2. Текст разбирается как статья: заголовок, подзаголовки блоков, строки, конец абзаца. Роль строки
   задаёт знак и паузу (`src/r11-plugins/ОЗВУЧКА.md`). Фраза — это одно состояние ролика, не короче 2 с.
3. Перечисление: точка у каждого слова. Чужие названия пишутся, как звучат. Ударение в трудном
   слове ставится значком в поле `"голосу"`.
4. Точное число, которое устареет от правки (время рендера), голосом не говорят: «меньше чем за
   минуту», а число стоит на экране.

**Голос.** Весь текст одним запросом и с одной манерой: `tools/voice-one.py`. По фразе не слать и
дубли замерами не отбирать. Манера берётся из монтажа: спокойный монтаж — спокойный голос.

**Звук.** `tools/sound.py`:
- музыка одной громкостью на весь ролик, тихо: `"музыка ровно": 0.07` (голос громче на 23–24 дБ);
- трек не короче ролика: длинный собирает `tools/loop.py`, ровный трек лучше рваного;
- звуковые эффекты из `public/sfx/lib`, общая громкость около 0,4; тихий свист на каждой смене сцены,
  иначе пауза голоса на смене слышна как провал; удары и нарастание приглушать отдельно;
- после сведения смотреть строку «музыка по 5 секунд»: она должна быть ровной до конца.

**Картинка.**
- Первый кадр — заставка: крупная надпись читается с нулевого кадра, резкая. Размытого и тусклого
  текста в первом кадре нет, зерна нет нигде: и то и другое читается как плохое качество.
- Полоса хода ролика появляется на смене первого кадра и идёт до самого конца. Полоса, которая
  заполнилась раньше конца, говорит зрителю, что ролик кончился.
- Субтитры по словам внизу, заголовок из 2–4 слов вверху. Важное не ниже 1500 и не правее 900.
- Крупное набрано Unbounded, остальное Onest. Сцены входят с разных сторон и с разной скоростью.
- В финале: куда идти и «сохрани».

**Сборка.** `sh tools/hf-render.sh <ролик>`: сборка страницы, `hyperframes check`, рендер. С ошибками
проверки рендер не идёт. После рендера — лист кадров глазами и первые кадры в полном размере.

**Чем рерайт проигрывал оригиналу (04.10.2026, r12 и r13, слово владельца «оригинал сильнее по
эффектам, крючку и тексту»).** Разбор в `src/r12-sites/ВЕРСИЯ-2.md` и `src/r13-rating/ВЕРСИЯ-2.md`. Отсюда правила:
- до сборки разложить оригинал и свой ролик листами с шагом 0,5 с, первые 10 с отдельно: что движется,
  чем крючок держит, где автор показывает доказательство (настоящий снимок поста, а не пересказ);
- голос течёт потоком: паузы 0,1–0,3 с, перемены внутри длинной фразы ставятся по словам. Манера
  `[confident narrator, brisk lively pace]`. Растяжка каждой фразы до 2 с сделала ролик на треть
  длиннее оригинала и вялым;
- ⛔️ **но картинка не мельтешит.** Голос бодрый, а смена кадра (новая сцена, весь экран другой) — не
  чаще раза в 2–2,5 с; внутри сцены за раз меняется одна вещь (слово заголовка, значок, клик, цифра),
  остальное стоит. Пролёт камеры — только между большими блоками. Владелец 04.10.2026 про вторые
  версии r12 и r13: «слишком быстрый темп смены кадров, человек может уставать психологически»;
  раньше: «тринадцать экранов за пятнадцать секунд — хаос» (правило ниже). Темп автора — не образец,
  если он быстрее этого;
- ⛔️ **ритм ровный:** у каждой фразы `"не короче": 2.3`, сцены ложатся в 2,3–3,2 с. Короткая сцена рядом с
  длинной читается как прыжок (владелец 04.10: «то долго не меняется, то быстро меняется»); замер — разброс
  длительностей сцен по `timeline.json`, держать его около 0,3 с;
- настоящее доказательство — настоящим снимком: пост из X или сайта снимается как есть (официальное
  встраивание поста, снимок страницы), а не перерисовывается своей вёрсткой;
- заголовок наверху и есть субтитры: фраза кусками по словам. Плакат + нижние субтитры + плашки — шум;
- свет меняется блоками, у каждой темы свой цвет; один лайм на весь ролик выглядит однообразно;
- живое видео, а не снимки: клипы Mixkit с лицензией Free (поле `copyrightNotice` на странице клипа);
- крючок — одна форма, которая меняется (стол → телефон с кадрами ролика → пустой экран), а не
  неподвижный плакат; барабан цифр, пролёт камеры на смене блоков, клик курсора как причина.

**Название и подпись.** По правилам `Style/выпуск.py`: название до 90 знаков словами поиска, подпись
до 80 знаков другим углом, 6–8 хештегов. Образец: `src/r11-plugins/ПОДПИСЬ.txt`.

## Приёмы на пробу: чему учиться у чужих роликов кодом

Разведка 03.10.2026. Источники: библиотека `guanmo-ai/awesome-ai-motion` (441 работа, почти все
сделаны кодом и Claude; учиться стоит на двух подробных промптах @twoclipping, остальные в одну
строку) и три репозитория из неё. У нас это ещё не пробовалось: каждый приём сперва идёт пробой.

**Монтаж**

| Приём | Что это | Что у нас сейчас |
|---|---|---|
| Одна форма, без склеек | один предмет превращается в следующий: размер, скругление, цвет; содержимое подменяется через короткое размытие. «Дорого» значит один предмет меняет форму, а не одна картинка сменяет другую | сцены перетекают, но каждая из своих предметов |
| Эстафета | один знак (точка, курсор) передаётся из сцены в сцену и не уходит с экрана | такого знака нет; кот появляется трижды, но не связывает сцены |
| Призрак начала | на месте, откуда предмет ушёл, остаётся бледный контур: глаз видит путь | нет |
| Курсор как причина | изменение вызывает клик или перетаскивание, а не «само появилось» | всё появляется само |
| Камера, а не раскладка | кадр наезжает так, что состояние заполняет его целиком; одна манера камеры на ролик | раскладка по центру |
| Слово становится интерфейсом | слово крючка превращается в окно продукта | крючок и окно — разные сцены |
| Раскрытие кругом | на сильную долю из кнопки открывается круг в другую сцену | вспышка на смене света |
| Края на разных пружинах | у плашки передний край уходит раньше заднего, она на миг вытягивается | края едут вместе |
| Жизнь в паузе | пока кадр держится, в нём живёт одна мелочь: бегунок, курсор, второй блик | в части сцен пауза пустая |
| Перевод фокуса | вместо анимации размытия — резкий слой и размытый слой с перетеканием: у Chrome размытие идёт ступенями | анимируем `blur()` напрямую |
| Петля | последний кадр равен первому, ролик зацикливается без шва | нет |

**Время**

- На каждый кадр выписать «прочтения»: что зритель должен понять и по порядку. Одно прочтение за
  раз; причина и отклик идут друг за другом, а не разом. Движение может быть быстрым, смысл держится.
  Перед важным моментом глаз ведут: туда смотрит герой, туда едет камера.
- Первые три секунды: если сам не остановил бы палец, переделать их до остального.
- Последнему прочтению нужно время сесть до конца ролика.

**Музыка и звук**

- Трек разбирается (`numpy`): темп, сетка ударов, сильная доля. Монтаж начинается на сильной доле,
  склейка на первой доле такта, событие на ударе. У ролика с голосом сетку даёт голос, но удары
  музыки под него всё равно можно подогнать.
- Звук ставится по пику, а не по началу файла: самый громкий миг эффекта попадает на событие.
  В `tools/sound.py` сейчас стоит начало файла.
- Времена звуков выгружаются из той же шкалы времени, что и картинка, одним файлом (у нас так).
- Итог приводится к −14 LUFS, пик не выше −1 dBTP. После сведения проверяется, что звук не уехал
  от картинки (у Remotion при сведении AAC остаётся сдвиг около 2,5 кадра).

**Размытие движения**

Каждый кадр считается из нескольких подкадров и усредняется. В ролике `claude-launchvideo` число
подкадров берётся из замера скорости (оптический поток): до 48 на быстрых перелётах, один на
неподвижных кадрах. Усреднять в числах с плавающей точкой и потом один раз округлять: если смешивать
в Chrome, мягкие градиенты идут кольцами. У HyperFrames свой справочник: `hyperframes-animation`,
`references/motion-blur.md`.

**Запреты из чужого вкуса** (не правило, но ролики автора собирают десятки тысяч закладок):
всплески частиц, вспышки фона, свечения, пружинящие отскоки, точки в надписях на экране. В r11 под
это попадают конфетти и вспышка на смене света: на следующем ролике попробовать без них.

**Выгрузка для площадок** (скил `reel-export` из `charlie947/motion-graphics-skills`):
H.264, `yuv420p`, диапазон `tv`, `bt709`, `+faststart`; файл в HEVC или с полным диапазоном площадка
перекодирует с вымыванием цвета. Автор держит слова между 360 и 1420 px по высоте и не правее
960 px; у нас заголовок начинается с 240 px. Наши поля сняты с TikTok, под Instagram верх стоит
сверить на телефоне.

**Что лежит в трёх репозиториях**

| Репозиторий | Что это | Что взять |
|---|---|---|
| `charlie947/motion-graphics-skills` (MIT, 13 скилов) | рабочие порядки автора: ролик запуска, объяснение в духе Vox, график, петля для обложки, выгрузка рилса | `motion-effects`: 16 рецептов «одна вещь превращается в другую» с временем каждой части; `vox-explainer`: типы кадров для объяснения и правила, снятые с забракованных версий |

## Как делать следующий ролик

Скилы лежат в `4xSoft/.claude/skills`, читать их до сценария.

Чужие наборы (HyperFrames, моушн-скилы, `impeccable`, Эмиль Ковальски, Fish Audio) лежат на складе
`4xSoft/.claude/склад` и подключаются по слову владельца «подключи скилы»: тогда под ролик берутся
`hyperframes` с семьёй, `motion-effects`, `vox-explainer`, `review-animations`, `reel-export`, `fish-audio-api`.
Всё, что нужно для ролика без них, записано в этой памятке.

| Шаг | Скил |
|---|---|
| Крючок и рассказ | `hook-generator`, `storytelling-corrector` |
| Тезис: что движется, чем и зачем, какие приёмы разрешены | `genjutsu` |
| Характер движения, длительности, сетка ударов | `motion-design` |
| Буквы по одной, линии, перетекание фигур | `gsap` |
| Настоящий объём, свет, тень | `threejs` |
| Числа с чужого ролика-референса | `design-dna` |

1. Тезис записать в шапке главного файла ролика: состояния, что движется, какие приёмы
   разрешены. ⛔️ Сценарий голоса, тезис и раскадровку по сценам показать владельцу и ждать
   «да» до первой строки сцен (слово владельца 14.10.2026: «не забудь выдать мне сценарий на
   одобрение»; так же требует `genjutsu`). Прежнее правило 29.09 «нести готовый ролик, а не
   сценарий» отменено. Пробную запись голоса до «да» делать можно, сцены нельзя.
   Образец — `src/r14-team/ТЕЗИС.md`.
2. Новая папка в `src/`, композиция в `Root.tsx`. Кривые движения и цвета брать из
   `lib/brand.ts`, сетку ударов из `lib/beat.ts`, а не подбирать заново.
3. Новый приём сначала проверяется пробой в `src/lab`.
4. Кадры каждого состояния и каждого перехода снять `stills` и посмотреть глазами.
   Сверить кадры с «привычками модели» из `genjutsu`.
5. Перед рендером проверить память: `sysctl vm.swapusage`. Рендер один, фоном.

## Объём в HyperFrames: Three.js под вёрсткой

Проверено на r14 (14.10.2026, владелец: «графика слабая, нужно больше 3D, движения и логики»). Если у ролика есть
`src/<ролик>/shared/three.js` с `export const buildThree = async (THREE, X, canvas, T, A) => (t) => {…}`, то
`tools/hf-build.mjs` сам кладёт Three.js из `node_modules` в `assets` (сети в рендере нет), ставит карту импортов,
модуль сцены и рисует кадр по событию `hf-seek`; готовность (шрифты, текстуры) — через `window.__hf.buildReady`.
В разметке сцен нужен `<canvas id="gl">` над фоном и под вёрсткой. Образец — `src/r14-team/shared/three.js`.

- Логотипы — настоящие файлы (`@lobehub/icons-static-svg`, `simple-icons`), знак выдавливается `SVGLoader` + `ExtrudeGeometry`
  с фаской. Тональная кривая `NeutralToneMapping`: с ACES терракота Claude выцветает в лососевый.
- Знак-герой не крутится вокруг оси, а покачивается (±0,5 рад): ребром он превращается в полоску и не читается.
- Сквозной герой даёт логику: один знак переходит из сцены в сцену и делает дело (отвечает, пишет код, ныряет в Telegram).
- Предметы на одной высоте не ставить вплотную: герой «на ступени» прятался внутри следующей.
- Надписи на холсте рисуются после `document.fonts.load`; значки Phosphor — `Path2D` по их `d`.
- Рендер 64 с с объёмом — около 50 с.

## Правила, проверенные на деле

- Первый кадр — обложка: герой смотрит в камеру, заголовок крупно, движение с первой доли секунды.
  Тёмный размытый фон с одним текстом владелец счёл поводом пролистать.
- Одна картинка дважды за ролик не ставится: начало и развязка — разные планы.
- Звук набора — записи настоящей клавиатуры, у нажатия и отпускания разные, ритм неровный.
  Звук клавиш, собранный кодом, владелец не принял.
- Состояние держится не меньше двух секунд. Тринадцать экранов за пятнадцать секунд
  владелец назвал хаосом.
- Один фон, одна манера движения, без отскоков.
- Текст не правее 900 px и не ниже 1500 px: там кнопки и подпись площадки.
- Поддельные рамки окон с тремя точками не рисовать.
- Слово Claude — терракотовое `#D97757`.
- Музыку модель не слышит. Темп и первый удар замеряются, а выбирает трек владелец.
- Смена состояния стоит на первой доле такта, акцент внутри состояния на ударе.
- Снимок героя на цветной странице сначала выравнивается `tools/flat.py`: иначе виден его край.
- Ждать чужой рендер — `pgrep -f "[h]yperframes@0.8.111 render"`, со скобкой. Без неё шаблон
  находит сам ждущий шелл (его строка команды содержит тот же текст), и цикл `until` не кончается
  никогда: 04.10.2026 очередь r12 так висела после конца рендера r13.
- Тег `<script>` внутри разметки сцен пишется с `<\/script>`: исходник сцен целиком лежит на странице
  внутри своего `<script>`, и голый закрывающий тег обрывает его (lint: `invalid_inline_script_syntax`).
- Надпись в текстуре рисуется только после загрузки шрифта: `fontsReady` из `lib/brand.ts`.
- В трёхмерной сцене нажатие клавиши, стоящей лицом к зрителю, не видно по ходу: её ещё и сжимают.
- Засветка от десятков накладных пятен света съедает картинку: пятно даётся только нажатой клавише.
